# 개인 PC 실행과 링크 접속

## GitHub 자동 반영

테스트 통과 후 Linux VM 또는 개인 PC에 자동 반영하는 구성은 [자동화 안내](AUTOMATION.md)를 참고하세요. Docker 볼륨에 저장을 유지하고 배포 직전 SQLite 백업을 만듭니다. 외부 서버 연결 전에는 GitHub 검사만 실행합니다.

## 로컬 검증

Python 3.11+를 설치합니다. 레포 루트에서 Windows `py -3 -m server.main`, macOS/Linux `python3 -m server.main`. 포트 변경은 `--port 8090`. Ctrl+C로 저장 후 종료합니다. 백그라운드 서비스 자동 등록은 이 패키지에서 하지 않습니다.

기본 주소는 127.0.0.1로 같은 PC에서만 접근합니다. LAN 테스트가 필요하면:

```sh
python -m server.main --host 0.0.0.0 --port 8080
```

이 경우 방화벽에서 필요한 사설 네트워크만 허용하고 다른 기기에서 PC의 실제 LAN IP를 사용합니다. `0.0.0.0`은 브라우저 접속 주소가 아닙니다. 원격 브라우저는 콘솔 링크의 호스트 부분을 LAN IP로 바꾸고 fragment 키를 유지합니다.

## 공개 링크의 목표 구성

브라우저 → HTTPS 공개 주소(역방향 프록시 또는 터널) → 개인 PC의 루프백 게임 서버. 서버 PC와 서버 프로세스가 켜져 있어야 합니다. 브라우저만 닫아도 서버는 계속 실행됩니다. 접속자 없으면 월드 시간은 정지합니다.

공개 주소 방식은 PC의 운영체제·업로드 회선·공유기·CGNAT·도메인 유무에 따라 선택합니다. 이 패키지는 외부 주소를 만들거나 방화벽·포트를 변경하지 않습니다. 특정 터널 공급자의 무료/유료 정책이나 설치 명령을 검증 없이 고정하지 않았습니다.

## 외부 공개 전 작업

현재 `http.server` 계층은 **비공개 개발용**입니다. Python 공식 문서도 생산용 HTTP 서버로 권장하지 않습니다. 소수 테스터에게 공개하기 전에도 다음을 수행합니다.

1. 유지 관리되는 웹 서버/프록시로 TLS 종료·요청 제한·연결 타임아웃 구성. 개발용 HTTP 계층을 생산용 서버로 교체하는 작업을 계획.
2. 게임 경로만 프록시하고 데이터베이스·키 파일·관리 포트는 노출하지 않음.
3. 단일 월드 키를 공개 링크 전체에 유포하지 않음. 멀티 출시 전 플레이어별 인증·복구·권한 구현.
4. 외부 네트워크에서 접속·새로고침·연결 중단·서버 재시작·과도한 요청을 테스트.
5. 백업 및 복구를 실제로 검증. PC 절전 정책과 업데이트 재부팅 시간 결정.

이 프로토타입은 링크 기반 실행 구조를 제공하지만 즉시 불특정 다수에게 공개할 완성 서비스는 아닙니다. 게임 내 과금은 없으며 개인 PC 전력·회선·선택적 도메인 비용까지 무료라는 의미는 아닙니다.

참고: [Python http.server 공식 문서](https://docs.python.org/3/library/http.server.html), [SQLite 공식 Python 모듈 문서](https://docs.python.org/3/library/sqlite3.html). 확인일 2026-10-26.
