# 테스트 계획

## 자동 검사

```sh
python -m unittest discover -s tests -v
node --check public/app.js
python tools/check_docs.py
```

게임 규칙: 제작 시설/재료/거리, 아지트 이동 자산 보존, 종족 왕복·연구 보존, 강화 확정 보정, 잘못된 이동, 채집 재사용 시간, 종족별 식사, 일시정지, 파견 1회 지급, 감염 복구, SQLite 왕복과 버전 오류.

HTTP: 접근 키 검증, 정적 경로 제한, 두 번째 브라우저 차단, 명령 저장, 이전 revision 재사용 거절, 실패 시 자원 보존, 형식 오류.

## 브라우저 수동 시나리오

1. 깨끗한 저장으로 인간 선택 → 주방 건설 → 수프 제작·사용.
2. 자원 지점 이동 → E 채집 → 인벤토리/로그/의뢰 수치 증가.
3. 강화 3회 → 단계 증가와 주문서 차감. 실패 구간은 테스트에서 확정 검증.
4. 안전한 다른 좌표에서 아지트 이동 → 시설 레벨·재고 보존.
5. 의료실 건설 → 뱀파이어 전환 → 연금대·강화혈액 → 인간 복귀.
6. 파견 출발 → 일시정지해 남은 시간 유지 → 재개 후 1회 보상.
7. 브라우저 새로고침 → 세션 임대 최대 4초 후 기존 캐릭터 복원.
8. 서버 종료/재시작 → 같은 DB 상태 복원, 종료 시간만큼 자원 소모 없음.
9. 두 번째 탭은 409 안내, 첫 탭 활동 중 제어 불가.
10. 키 없는 접속은 API 거절, 정적 페이지는 표시 가능.

## 후속 공개 전 검증

외부 네트워크·HTTPS·키 재발급·인증·요청 제한·장시간 AI 부하·백업 복구·브라우저별 입력. 현재 이 환경의 로컬 브라우저 검증을 개인 PC나 실제 인터넷 접속 검증으로 간주하지 않습니다.

검증 실행 결과는 VALIDATION.md에 기록합니다.
