# 0.5.1 렌더링·입력 검증

2026-10-27, 동일 클라우드 환경의 headless Chromium에서 0.5.0과 수정본을 비교했습니다. 서버·저장 없이 동일 64×64 월드와 이미지를 로드하고, 장면별 70프레임 중 초기 11프레임을 제외합니다. 이동 좌표는 매 프레임 같은 양으로 바꿉니다. 모바일은 370×580 Canvas, DPR 2를 모사합니다.

| 장면 | 그리기 중앙값 전→후 | 프레임 간격 중앙값 전→후 | 그리기 P95 전→후 |
| --- | --- | --- | --- |
| 아지트 1280×720 | 13.3 → 5.3ms | 19.7 → 16.7ms | 14.7 → 8.7ms |
| 숲 1280×720 | 15.9 → 6.1ms | 26.3 → 18.4ms | 19.2 → 8.4ms |
| 모바일 숲 | 10.6 → 5.2ms | 23.9 → 16.6ms | 14.7 → 8.0ms |

이는 이 환경의 한 비교 실행 결과이며 실제 사용자 장치의 FPS를 보장하지 않습니다. 그리기 시간은 `WorldView.draw` 호출의 JS 경과 시간이고 프레임 간격은 requestAnimationFrame 간격입니다. 이미지 다운로드·첫 캐시 생성은 준비 구간이며 표에 포함하지 않습니다. 원본 PNG 11장은 유지됩니다.

재현: Playwright와 Chromium이 있는 환경에서 `node tests/render_performance.cjs`. 네트워크 대신 로컬 파일 경로를 가로채므로 개인 저장과 접속 키를 사용하지 않습니다. 결과 JSON은 콘솔에만 출력합니다. CI는 시간 임계치 대신 캐시 재사용·좌표·입력 동작을 검증합니다.

`node tests/client_navigation.cjs`는 지연 응답, 한 걸음 예측, 상태 불변성, 키 해제, 방향 전환, 거절 복구와 경계를 확인합니다. `node tests/browser_smoke.cjs`는 실제 이동 HTTP 요청을 400ms 지연시켜 서버 승인 전 화면 반응과 키 해제 후 추가 이동 방지를 확인합니다. 서버의 100ms 이동 쿨다운과 클라이언트 140ms 이동 주기는 유지합니다. 예측은 서버가 승인한 이동으로만 확정되며 미래 입력을 누적하지 않습니다.


## 0.7.0 넓은 월드

128×128 확장에서는 전체 지형 비트맵을 만들지 않습니다. 16×16 월드 조각(1092×548 픽셀)만 미리 투영해 캐시하고 현재 화면에서 벗어난 조각을 오래된 순서로 제거합니다. 기본 보유 예산은 모바일 12개·데스크톱 24개이며, 현재 화면에 더 많은 조각이 필요하면 그 개수까지만 유지합니다. 장식 배치는 지도 구성 변경 시에만 계산합니다.

현재 `tests/render_performance.cjs`의 아지트 좌표는 (22,23), 숲은 (78,30)입니다. 같은 클라우드 환경의 확장 후 한 실행에서 그리기 중앙값은 아지트/숲/모바일 숲 모두 약 0.5ms, 프레임 간격 중앙값은 약 16.7ms였습니다. 위 0.5.1 표와는 지형·오브젝트 밀도가 달라 직접적인 동일 장면 비교가 아닙니다. 첫 캐시 생성·다운로드를 제외한 측정이며 실제 장치 FPS를 보장하지 않습니다.
